# PRD: ZanWatch — мониторинг изменений законодательства РК

**Сфера:** бухгалтерский учёт, налоги, зарплата и взносы, страховая деятельность, аудит
**Юрисдикция:** Республика Казахстан
**Статус:** MVP реализован (код, тесты, демо интерфейса). Боевой сбор с источников пока не запускался
**Дата:** 27.11.2026

---

## 1. Проблема

Законодательство в сфере учёта, налогов и страхования в РК меняется часто. Изменения публикуются на нескольких сайтах, а сами документы написаны канцелярским языком. Акты «о внесении изменений» содержат только правки («слова «X» заменить словами «Y»»), поэтому понять, что поменялось по существу, можно только сопоставив их с действующей редакцией.

Чтобы понять, касается ли изменение его компании и что делать, специалисту приходится:
- регулярно просматривать несколько сайтов;
- читать десятки страниц текста;
- самому выводить из текста сроки и нужные действия.

Это отнимает время и создаёт риск пропустить важное изменение: новую форму отчётности, ставку, норматив или срок.

## 2. Цель продукта

Пользователю не нужно читать 50 страниц канцелярского текста. По каждому изменению приложение даёт короткую карточку:

1. **Суть.** Что произошло, в 2–3 предложениях простым языком.
2. **Было → стало.** Конкретные правки с указанием статьи или пункта.
3. **Что нужно сделать.** Чек-лист действий со сроками.

К карточке всегда прилагается ссылка на первоисточник.

## 3. Целевая аудитория

| Роль | Что важно | Сферы |
|---|---|---|
| **Бухгалтер** | Формы отчётности, ставки, план счетов, сроки сдачи, ЭСФ | Бухучёт, налоги, зарплата и взносы, аудит |
| **Юрист** | Законы, изменения в договорах и правилах, правовые риски | Налоги, страхование |
| **Специалист страховой компании** | Пруденциальные нормативы, резервы, ОГПО, требования АРРФР | Страхование |

## 4. Источники данных

| Источник | Тип | Статус | Роль |
|---|---|---|---|
| adilet.zan.kz (ИПС «Әділет») | НПА | Официальный | Главный источник нормативных актов |
| АРРФР (gov.kz/memleket/entities/ardfm) | НПА | Официальный | Регулирование страхового рынка |
| Минфин РК (gov.kz/memleket/entities/minfin) | НПА | Официальный | Методология бухучёта, план счетов, ДФО |
| kgd.gov.kz | Разъяснения | Официальный | Налоговое администрирование, разъяснения КГД |
| uchet.kz | Обзоры | Неофициальный | Аналитика и обзоры |
| zan.kz | Обзоры | Неофициальный | Новости законодательства |

Неофициальные источники в интерфейсе помечены как «Обзор», и пользователю предлагается сверяться с текстом НПА.

## 5. Функциональные требования (MVP)

### 5.1. Сбор и обработка

| # | Требование | Реализация |
|---|---|---|
| F1 | Периодически собирать новые документы из источников | `collector.py`, `pipeline.py`; запуск по расписанию (`ZW_COLLECT_INTERVAL_HOURS`), из CLI или через API |
| F2 | Соблюдать robots.txt и не перегружать сайты | Проверка robots.txt, пауза между запросами (по умолчанию 2 с) |
| F3 | Не обрабатывать документ повторно | Уникальность по URL, хэш текста |
| F4 | Отсекать документы не по теме до вызова ИИ | `classifier.py`: словари по сферам с весами; первый фильтр по заголовку, второй по полному тексту |
| F5 | Определять сферы документа и затронутые роли | Классификатор + сопоставление «сфера → роль» |
| F6 | Извлекать «было/стало» из актов об изменениях без ИИ | `amendments.py`: шаблоны «заменить», «изложить в редакции», «дополнить», «исключить» |
| F7 | Определять дату вступления в силу | Поиск в тексте фраз «вводится в действие / вступает в силу с …» |
| F8 | Формировать ИИ-сводку: суть, правки, действия, сроки, важность | `summarizer.py`, Claude API; найденные правилами правки передаются ИИ как подсказка |
| F9 | Работать без ИИ | Если ключа нет или вызов не удался, сводка строится по правилам |
| F10 | Не допускать выдуманных норм | Промпт запрещает додумывать; нет данных — поле пустое; ответ проверяется по схеме |

### 5.2. Интерфейс пользователя

| # | Требование |
|---|---|
| U1 | Лента изменений: сверху «Требует действий» (важность high), ниже остальные |
| U2 | Выбор роли при первом запуске (бухгалтер / юрист / страховщик / все); лента фильтруется по роли |
| U3 | Фильтр по сферам (чипы) и полнотекстовый поиск по сводкам |
| U4 | Карточка в ленте: важность, сферы, заголовок, суть в 2 строки, источник, дата публикации, дата вступления в силу с обратным отсчётом |
| U5 | Экран документа: суть, ключевые факты (дата вступления, источник), блоки «было → стало», чек-лист действий со сроками, кнопка «Открыть первоисточник» |
| U6 | Отметка выполненных действий (хранится на устройстве) |
| U7 | Вкладка «Сроки»: все невыполненные задачи по всем документам в календарном порядке; сроки ближе 14 дней подсвечиваются |
| U8 | Избранное |
| U9 | «Поделиться»: системное меню телефона или копирование текста |
| U10 | Установка на телефон как приложение (PWA), офлайн-доступ к последней загруженной ленте |
| U11 | Под каждой сводкой предупреждение: «Сводка подготовлена автоматически, сверяйтесь с первоисточником» |
| U12 | Демо-карточки явно помечены «Демо», над лентой показывается баннер |

### 5.3. Уровни важности

| Уровень | Критерий |
|---|---|
| **Важно** (high) | Меняются ставки, сроки, формы отчётности, штрафы, требования к капиталу или резервам |
| **Средне** (medium) | Процедурные изменения |
| **Справочно** (low) | Уточнения и разъяснения без новых обязанностей |

## 6. Модель данных

**documents** — сырые документы из источников
`id, source, url (уникальный), title, published_at, raw_text, content_hash, status (new | relevant | irrelevant | processed | error), relevance, error, fetched_at`

**updates** — готовые карточки для пользователя
`id, document_id, source, url, doc_title (официальное название), title (понятный заголовок), doc_kind (npa | explanation | news), spheres[], audience[], importance, summary, changes[{where, was, became}], actions[{text, deadline, who}], effective_date, published_at, ai_model, is_demo, created_at`

**runs** — журнал запусков сбора
`id, started_at, finished_at, stats`

Справочники:
- сферы: `accounting`, `tax`, `payroll`, `insurance`, `audit`;
- роли: `accountant`, `lawyer`, `insurer`.

## 7. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/updates?sphere=&audience=&importance=&source=&q=&limit=&offset=` | Лента с фильтрами |
| GET | `/api/updates/{id}` | Карточка изменения |
| GET | `/api/meta` | Справочники сфер, ролей, источников; время последнего сбора |
| POST | `/api/collect` | Запуск сбора (заголовок `X-Admin-Token`) |

## 8. Архитектура и стек

```
Источники → Сбор списка → Фильтр по заголовку → Загрузка текста → Фильтр по тексту
         → Разбор правок по правилам → ИИ-сводка (Claude) → SQLite → FastAPI → PWA
```

| Компонент | Технология |
|---|---|
| Бэкенд | Python 3.11+, FastAPI, Uvicorn |
| Сбор и парсинг | httpx, BeautifulSoup, lxml |
| ИИ | Claude API (модель задаётся через `ZW_LLM_MODEL`) |
| Хранение | SQLite, схема переносима в PostgreSQL |
| Фронтенд | Один HTML-файл на чистом JS, mobile-first, PWA (manifest + service worker) |
| Тесты | pytest |

Разметка сайтов-источников вынесена в конфиг (`app/config.py`). Если вёрстка сайта изменится, правится только конфиг, код трогать не нужно.

## 9. Нефункциональные требования

| Область | Требование |
|---|---|
| Достоверность | Каждая сводка ссылается на первоисточник; ИИ не додумывает нормы; виден способ подготовки (модель ИИ или правила) |
| Этика сбора | Соблюдение robots.txt, паузы между запросами, понятный User-Agent |
| Надёжность | Сбой одного источника или ИИ не останавливает конвейер; ошибки пишутся в журнал запусков |
| Безопасность | Запуск сбора через API защищён токеном; токен по умолчанию нужно сменить |
| Производительность | Лента открывается за ≤ 1 с на мобильном интернете; MVP рассчитан на сотни карточек |
| Конфиденциальность | В MVP нет регистрации; роль, избранное и отметки хранятся на устройстве пользователя |
| Язык | Интерфейс и сводки на русском |

## 10. Метрики успеха

| Метрика | Цель MVP |
|---|---|
| Полнота: доля значимых НПА за период, попавших в ленту | ≥ 90% (проверяется по ручной выборке) |
| Точность «было/стало» и дат по проверке юриста | ≥ 95% без существенных ошибок |
| Доля нерелевантных карточек в ленте | ≤ 10% |
| Задержка от публикации до появления в ленте | ≤ 24 часа |
| Время, чтобы понять суть изменения | ≤ 1 минуты на карточку |
| Удержание пилотных пользователей через 4 недели | ≥ 40% |

## 11. Текущий статус

**Готово:**
- бэкенд: сбор, фильтрация, разбор правок, ИИ-сводка, API;
- мобильный интерфейс: лента, роли, карточка, сроки, избранное, PWA;
- 6 автотестов (разбор правок, классификатор, извлечение из HTML, API) проходят;
- 7 демо-карточек для показа формата;
- опубликовано демо интерфейса.

**Не проверено:**
- реальный сбор с сайтов. Из среды разработки они были недоступны, поэтому адреса лент и CSS-селекторы заданы по типовой вёрстке и требуют сверки;
- качество ИИ-сводок на реальных документах.

## 12. Риски и ограничения

| Риск | Мера |
|---|---|
| Сайты меняют вёрстку, и сбор ломается | Селекторы вынесены в конфиг; в журнале запусков видны источники с ошибками |
| ИИ ошибается в норме или сроке | Подсказки из разбора по правилам, запрет на домысливание, предупреждение, ссылка на первоисточник, в планах кнопка «неточность» и выборочная проверка юристом |
| Условия использования сайтов | Изучить условия adilet.zan.kz; с коммерческими порталами (uchet.kz, zan.kz) договориться о доступе; приоритет открытым данным Минюста, если они доступны |
| Документы на казахском языке | MVP собирает русские версии; казахские подключаются отдельным источником |
| Демо-данные примут за реальные | Метка «Демо», баннер, отключение настройкой `ZW_SEED_DEMO=0` |

## 14. Дорожная карта

| Этап | Содержание |
|---|---|
| **0. Запуск MVP** | Сверить селекторы источников, первый реальный сбор, проверка 30–50 сводок юристом, отключить демо |
| **1. Пилот** | 10–20 пользователей из целевых ролей; кнопка «неточность»; замер метрик из раздела 10 |
| **2. Уведомления** | Web Push / FCM и Telegram-бот по ролям и сферам; еженедельный дайджест |
| **3. Аккаунты** | Синхронизация избранного и чек-листов; общие командные чек-листы внутри компании |
| **4. Точность** | Сравнение редакций «до и после» по данным Әділет; мониторинг проектов НПА (legalacts.egov.kz) |
| **5. Масштаб** | PostgreSQL, очередь задач (Celery / RQ), нативное приложение (Capacitor / React Native), казахский язык |

## 15. Запуск (для разработчика)

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # без ключа — разбор только по правилам
export ZW_ADMIN_TOKEN=...
uvicorn app.main:app --host 0.0.0.0 --port 8000
python -m app.pipeline              # ручной сбор
pytest -q                           # тесты
```
